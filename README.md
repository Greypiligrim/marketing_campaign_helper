# Marketing Service (Web API)

Веб-сервис для управления маркетинговыми кампаниями с AI: классификация сообщений,
парсинг описания кампании, разбиение на подзадачи (по подходящему шаблону или
свободно через LLM), ответы на вопросы. Раньше был Telegram-ботом — теперь это
REST API + веб-чат с боковой панелью кампаний и шаблонов.

Пользователь представляется именем и ролью (хранится в браузере, без паролей);
имя/роль сохраняются в кампании (`created_by`), а при разбиении по шаблону
ответственные за подзадачи подбираются из участников с указанием роли из шаблона.

## Используемые библиотеки

- **fastapi** + **uvicorn** — веб-фреймворк и ASGI-сервер
- **sqlalchemy** + **aiosqlite** — ORM и асинхронная работа с SQLite
- **aiohttp** — асинхронный HTTP-клиент (запросы к OpenRouter)
- **dateparser** — парсинг дат
- **python-dotenv** — переменные окружения

## Быстрый старт

```bash
pip install -r requirements.txt
```

Создайте `.env`:
```
OPENROUTER_API_KEY=sk-or-v1-...
DEBUG=True
# опционально:
# HOST=0.0.0.0
# PORT=8000
```

Запуск:
```bash
python main.py
# или: uvicorn web.app:app --reload
```

Откройте http://127.0.0.1:8000/ — веб-чат. Документация API: http://127.0.0.1:8000/docs

## API

| Метод  | Путь                       | Описание |
|--------|----------------------------|----------|
| POST   | `/api/chat`                | Отправить сообщение (`message`, опц. `user_name`, `user_role`). Ответ: `question` / `other` (текст), `campaign` (preview + `pending_id`) или `clarify` (не хватает данных — список `missing`, можно дослать сообщением) |
| POST   | `/api/campaigns/refine`    | Дозаполнить ожидающую кампанию данными из нового сообщения (`pending_id`, `message`) |
| POST   | `/api/campaigns/confirm`   | Подтвердить создание кампании по `pending_id` (опц. `user_name`, `user_role` → `created_by`) |
| POST   | `/api/campaigns/cancel`    | Отменить ожидающую кампанию |
| GET    | `/api/campaigns`           | Список кампаний с подзадачами (поля `created_by`, `template_used`) |
| DELETE | `/api/campaigns/{name}`    | Удалить кампанию по названию |
| GET    | `/api/templates`           | Список шаблонов |
| GET    | `/api/templates/{name}`    | Детали шаблона |
| POST   | `/api/templates`           | Добавить шаблон (есть форма в веб-интерфейсе) |
| PUT    | `/api/templates/{name}`    | Редактировать шаблон (тело — как у POST; `name` в теле = новое имя) |
| DELETE | `/api/templates/{name}`    | Удалить шаблон |
| GET    | `/api/users`               | Список участников чата (имя + роль) |
| POST   | `/api/users`               | Зарегистрировать/обновить участника (`name`, опц. `role`) |
| DELETE | `/api/users/{name}`        | Убрать участника из списка |
| GET    | `/api/reminders/today`     | Подзадачи с дедлайном сегодня (замена напоминаний из job_queue) |
| GET    | `/api/health`              | Проверка живости сервиса (`{"status":"ok"}`) |

При создании кампании LLM выбирает подходящий шаблон из существующих; если выбран —
подзадачи считаются детерминированно (бюджет = % от общего, срок = доля от дней до
дедлайна), иначе — свободное разбиение через LLM. Имя применённого шаблона
сохраняется в `Campaign.template_used`.

Все данные — в одном общем пространстве (поле `chat_id` в БД больше не используется).
Распарсенные, но не подтверждённые кампании хранятся в БД (таблица `pending_campaigns`),
переживают перезапуск и автоматически чистятся через `PENDING_TTL_HOURS` часов.

## Docker

```bash
docker build -t marketing-service .

```

## Деплой на Render (бесплатно)

В репозитории есть `render.yaml` (blueprint) и `Dockerfile`.

1. Запушьте репозиторий на GitHub.
2. На [render.com](https://render.com) → **New +** → **Blueprint** → выберите этот репозиторий → **Apply**.
   (Render найдёт `render.yaml` и создаст бесплатный web-сервис на Docker с health-check `/api/health`.)
3. Откройте созданный сервис → **Environment** → добавьте `OPENROUTER_API_KEY` со своим ключом → **Save** (сервис передеплоится).
4. После сборки приложение доступно по адресу вида `https://marketing-bot.onrender.com/`.

Замечания:
- Бесплатный тариф **засыпает после ~15 минут простоя** — первый запрос после простоя отвечает с задержкой ~30–60 с.
- Файловая система эфемерная: SQLite-файл (`marketing_bot.db`) сбрасывается при каждом редеплое/перезапуске. Для постоянных данных подключите внешнюю БД (вынести `DATABASE_URL` в переменную окружения).
- `PORT` Render задаёт сам — приложение его подхватывает; `HOST=0.0.0.0` уже выставлен в `Dockerfile`.

## Структура проекта

- `config/` — настройки, встроенные шаблоны кампаний
- `db/` — модели данных (Campaign, Subtask, Template)
- `ml/` — LLM-интеграция и промпты
- `core/service.py` — бизнес-логика (без привязки к транспорту)
- `web/app.py` — FastAPI-приложение (REST + статика)
- `web/static/index.html` — веб-чат + боковая панель (кампании, шаблоны, дедлайны), форма добавления шаблона, логин (имя+роль)
- `main.py` — запуск веб-сервиса
- `main_telegram_legacy.py` — прежний Telegram-бот (для справки, требует `python-telegram-bot`)
